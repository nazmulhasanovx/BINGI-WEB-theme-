================================================================
 P0  -  BLOCKERS (owner cannot finish)
================================================================

[ONB-P0-01] "Continue" from My properties fails
  WHERE     /onboarding -> My properties -> pick a property -> Continue
  HAPPENS   List loads, then "Could not load onboarding. Unauthenticated."
  IMPACT    Owner who stopped half-way cannot come back.
  EXPECTED  Opens the saved step. If session expired: sign in -> return
            to the same property + step.
  FIX       BE/FE: list call and load call use different auth (cookie vs
            bearer, or scope). Use one session.

[ONB-P0-02] "Try again" opens a DIFFERENT property
  WHERE     Error screen of ONB-P0-01 -> Try again
  HAPPENS   Opens /dashboard/setup-center of "Pan Pacific Sonargaon
            Dhaka" (10/13 steps).
  IMPACT    Owner may edit the wrong hotel.
  EXPECTED  Retry the SAME property.
  FIX       FE: keep property id on retry; never fall back to "last
            used" property.
  CHECK     Does that property belong to the same login? (phone on My
            properties and account row differed)

[ONB-P0-03] Only the FIRST room type can be saved
  WHERE     3.2 Add rooms -> 2nd type -> Save
            (Garden Cottage, Private Villa, 2-Bedroom Apartment, Suite,
            Twin Room - all fail)
  HAPPENS   POST /api/onboarding/accommodation-categories
            403 {"code":"KYC_TRIAL_CATEGORY_LIMIT"}
            UI shows a generic error above the fold.
  IMPACT    Resort cannot add cottages/villas; hotel cannot add a 2nd
            room type. Main job of onboarding is blocked.
  EXPECTED  Decision D2: unlimited drafts before KYC.
  FIX       BE: remove KYC_TRIAL_CATEGORY_LIMIT for onboarding drafts.
            FE: map every API error code to a plain sentence.

[ONB-P0-04] Checkout sells a different plan
  WHERE     2.4 Start -> Subscribe now -> Go to checkout
  HAPPENS   Page "BinGi Ultra - BDT 3,500" but URL
            ?plan=PLAN_ENTERPRISE
  IMPACT    Payment order may be made for Enterprise.
  FIX       FE/BE: one plan id from plan step -> checkout -> payment;
            checkout reads plan, rooms, period from one source.

[ONB-P0-05] Payment blocked by KYC at the end
  WHERE     Checkout -> Continue to secure payment
  HAPPENS   "Complete hotel KYC verification to access this HMS module."
            No way forward.
  EXPECTED  Decision D3: subscription payable before KYC.
  FIX       BE: allow subscription checkout without KYC.
