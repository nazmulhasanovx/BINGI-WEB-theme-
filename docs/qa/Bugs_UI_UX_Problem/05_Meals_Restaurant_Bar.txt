 P0 - FIX FIRST
================================================================

[MEAL-P0-01] Restaurant Settings cannot be saved
  WHERE     Meals -> Settings -> Charges (VAT 15, service 10) -> Save
  HAPPENS   POST https://api.bingi.app/api/meals/settings -> 422
            {"message":"The qr logo field must be an image.",
             "errors":{"qr_logo":[... must be a file of type:
             jpeg, png, jpg, svg, webp]}}
            Screen shows nothing. Values look saved but are not:
            next POS order still had no VAT / service charge.
  IMPACT    Owner cannot change VAT, service charge, hours, pause,
            approvals, printing - and thinks he did.
  FIX       FE: do not send qr_logo when no new file was picked
            (send nothing, or keep existing path).
            BE: make qr_logo optional ("sometimes|image").
            FE: show save errors.

[MEAL-P0-02] Guest QR orders ignore "Pause" and "Counter approval"
  WHERE     Settings -> Ordering: "Pause accepting orders" = ON,
            "Require counter approval for QR orders" = ON
            Guest opens table QR -> adds dish -> Place order
  HAPPENS   Order FO-2026-000071 accepted. Status "Confirmed",
            Approval status "Accepted", sent straight to kitchen
            (Queued). Approvals tab = 0.
            Guest menu shows no "paused" notice; Add works.
  IMPACT    Restaurant cannot stop or check guest orders. Kitchen
            gets orders it did not agree to.
  EXPECTED  Pause ON -> guest menu shows "Not taking orders now",
            order is refused (also by the API).
            Counter approval ON -> order waits in Approvals.
  FIX       BE: check both settings when a QR / guest order is
            created. FE: guest menu reads pause state.
  NOTE      Check again after P0-01 is fixed (settings may be
            stored but not read, or not stored).

[MEAL-P0-03] Payment cannot be taken for a Table QR order
  WHERE     Orders -> FO-2026-000071 (Table QR) -> Collect payment
  HAPPENS   PATCH https://api.bingi.app/api/meals/orders/
            FO-2026-000071/payment -> 500 {"message":"Server Error"}
            Tried Cash (৳250 and ৳500 received) and bKash with a
            reference. Same 500 each time.
            The same steps on a POS order (OFO-2026-000013) work.
  IMPACT    Every guest who orders by QR cannot be charged.
  FIX       BE: check server log for this endpoint with QR / dine-in
            orders (guest-created order, no staff, table source).

[MEAL-P1-01] Menu is not linked to Inventory
  WHERE     Menu item, POS sale
  HAPPENS   4 x QA Fried Rice sold; Inventory "QA Rice" stayed
            113 kg. Menu "Cost price" is typed by hand.
  EXPECTED  Menu item links to an Inventory recipe. A served /
            paid order takes ingredients out of stock. Cost price
            comes from the recipe.  (Same as INV-P1-07.)

[MEAL-P1-02] Discount price higher than price is accepted
  WHERE     Menu -> Add item
  HAPPENS   Regular ৳250, Discount price ৳300 -> saved.
  EXPECTED  Discount price must be lower than regular price.

[MEAL-P1-03] Reports and Overview show old numbers
  WHERE     Reports after new orders
  HAPPENS   Showed 1 order / ৳146 / collected ৳0 while 4 orders and
            ৳827 collected existed. Correct only after Refresh.
  EXPECTED  Numbers update when orders change (or refetch on
            opening the tab).

[MEAL-P1-04] QR order on a busy table becomes a second bill
  WHERE     Table "Hamim" had open order FO-2026-000070;
            guest ordered by QR at the same table.
  HAPPENS   New separate order FO-2026-000071. Tables & QR still
            shows the table as "Ready".
  EXPECTED  One running bill per table visit (QR adds items to it),
            table shows "Occupied" while a bill is open.

[MEAL-P1-05] POS "Send for approval" goes straight to kitchen
  WHERE     POS approval policy = "Require counter approval"
  HAPPENS   Admin's POS orders went to Queued; Approvals = 0.
  EXPECTED  If admin skips approval, button says "Send to kitchen".
            Check with a staff login that staff orders do wait.

[MEAL-P1-06] Two "bKash" payment choices, no card
  WHERE     POS "Collect payment now", Collect Payment drawer
  HAPPENS   Cash, bKash, bKash. Clicking the first bKash highlights
            the second.
  EXPECTED  Show each account with its label/number
            (e.g. "bKash Merchant 01XX"), one selection, add Card if
            the hotel accepts it.

[MEAL-P1-07] "Receipt preview" opens the print dialog directly
  WHERE     Order details -> Receipt preview
  HAPPENS   Browser print dialog opens and blocks the page.
  EXPECTED  Show the receipt on screen first, with Print / Share.
